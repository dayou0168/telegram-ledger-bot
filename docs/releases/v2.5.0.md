# Go v2.5.0

v2.5.0 replaces continuous Tronscan polling with a Lite/Kafka-first transfer pipeline while retaining automatic API failover.

## Chain event pipeline

- Consumes `tron.pending` for low-latency TRX and USDT transfer alerts.
- Consumes normalized `tron.confirmed` events for block-level recovery and final success/failure state.
- Commits Kafka offsets only after durable PostgreSQL persistence.
- Uses a canonical movement key to deduplicate Pending, Confirmed, and API observations.

## Notification behavior

- Pending first: sends the normal transfer notice immediately.
- Confirmed success after Pending: updates state silently.
- Confirmed failure after Pending: sends one failure warning.
- Confirmed first: sends the normal transfer notice; failed transactions include an explicit failed status.
- Adds TRX transfer support without changing the existing USDT notice layout.

## API failover

- Normal Kafka operation does not run Tronscan scans or key probes.
- A Confirmed stream that remains stale for 15 seconds activates the existing multi-key Tronscan USDT scanner.
- Kafka recovery stops API scanning automatically after Confirmed catches up.
- The bot's existing shared public fallback remains the final safety layer if both Kafka and the watcher API-key lane fail.

## Deployment

Configure the watcher with `CHAIN_WATCHER_SOURCE_MODE=kafka`, both Kafka topics, and a unique consumer group. Kafka port `29092` should only permit the robot server address. PostgreSQL migrations create the lifecycle state table automatically.
